# 排课系统模块化重构计划

## Context（背景）

当前项目 `d:\代码\field-demo` 是一个 **单文件 `index.html`（~60KB）**，所有 CSS / HTML / JS 全部内联，实现了月度排课系统（上传师资空闲时间表 + 课程体系表 Excel → 智能排课 → 日历可视化）。

随着功能迭代（分散策略、时间优先级、两级排课、列表删除联动等），单文件已难以维护：
- 函数全部挤在同一闭包，状态为全局变量，删除联动逻辑散落各处；
- 无法独立测试排课算法；
- 输入/输出界面混在一起，可视化不清晰。

**目标**：保留 `index.html` 完全不动，在 `app/` 子目录新建一套 **原生 JS + Vite** 模块化工程，输入区与输出区 **上下分区可视化**，行为与原系统一致。

## 用户决策
- 技术栈：原生 JS + Vite（无框架，仅 xlsx 依赖）
- 布局：上下分区（上=输入，下=输出）
- 现有 `index.html`：完全保留不动

## 核心设计要点

### 1. 状态管理（pub/sub）
- `store.js` 维护单一 state：`{currentDate, selectedDate, availabilityData[], courseSystemData[], courses[], statuses}`
- 导出 `getState/setState/subscribe` + 细粒度 action（`setAvailability/setCourseSystem/setCourses/runSchedule/deleteAvailability/deleteScheduledCourse/deleteCourseSystemItem`）
- **删除联动一致性在 action 内完成**（不在 render 层）：
  - `deleteScheduledCourse(idx)`：删 courses，并按 `id-100` 把 `courseSystemData[i].scheduled` 置 `null`
  - `deleteCourseSystemItem(idx)`：若 `scheduled===true` 同步删 courses 对应项，再删 courseSystemData

### 2. 排课算法纯函数化
- 原 `findBestDispersionPlan` / `tryScheduleCourse` 深度依赖闭包，提取为模块函数时显式传参：`monthAvailability`、`teacher`、`ctx`
- `scheduleContext.js` 封装 `teacherScheduleByDate`/`classScheduleByDate`/`scheduledCourses` 三个可变映射 + `registerSlot()`，解决闭包捕获问题
- `generateSchedule(state)` 为纯函数：不读 DOM、不调 render，返回结果由 store action `runSchedule()` 落账后触发重绘
- 修复原 `teacherHasCourseOnDay` 未初始化的潜在 TypeError（该变量仅写不读，可安全移除）

### 3. 新布局（上下分区）

### 4. 事件委托（关键迁移点）
- 原代码用内联 `onclick="deleteXxx(index)"`，模块化后重渲染会失效
- 改为在 `availabilityListContent`/`scheduledListContent`/`courseSystemBody` 容器上委托 click，按 `data-action="delete"` + `data-index` 路由到 store action

### 5. 依赖与运行
- `package.json`：`dependencies: xlsx@^0.18.5`、`devDependencies: vite@^5.4.0`
- XLSX 由 CDN 改为 npm import
- 运行：`cd app && npm install && npx vite`（自动开 localhost:5173）

## 实施顺序（每步可独立验证）
1. 搭 `app/` 脚手架（package.json/vite.config.js/index.html 空骨架/main.js）→ 跑通 `npx vite`
2. 迁 CSS → 7 个文件 + index.css 聚合 → 静态样式正常
3. 迁 `dateUtils` + `constants` → 纯函数
4. 建 `store` + `selectors` → main.js 首屏渲染空状态
5. 迁 `excelParser` → 接上传事件，验证列表渲染
6. 迁 `render` 模块（calendar/courseSystem/dataLists）→ 接 store 订阅
7. 迁 `scheduler`（timePriority/dispersion/scheduleContext/trySchedule/index）→ 排课按钮
8. 迁删除联动（store actions + 事件委托）
9. 响应式断点微调
