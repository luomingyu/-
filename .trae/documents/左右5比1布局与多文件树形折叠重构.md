# 左右 5:1 布局与多文件树形折叠重构

## Context（背景）

当前 `app/` 应用是**上下布局**：上方输入区（上传卡片 + 三列数据列表），下方日历。上传为**单文件替换模式**（每次上传整个替换 `availabilityData` / `courseSystemData`），数据列表是扁平条目流。

用户要求改为：
1. **左右 5:1 布局**：左侧课表（日历），右侧表格汇总。
2. 右侧汇总含三个区块：**师资空闲时间表、课程体系表、排课结果**。
3. **多文件累积上传**：支持多次上传累积，每个文件作为一个可折叠节点（类似电脑文件夹），点击展开显示该文件内的详细条目，文件与条目均可单独删除。
4. 课程体系表在窄列下用**紧凑表格 + 横向滚动**展示。

经 AskUserQuestion 确认的三个设计决策：多文件累积+树形展开；排课结果保留为第三个折叠区；课程体系表用紧凑表格+横向滚动。

## 设计方案

### 数据模型（核心：文件分组 + 派生扁平缓存）

为最小化对排课算法/日历的影响，**真实存储改为「按文件分组」，同时保留扁平数组作为派生缓存**。`scheduler/index.js`、`calendar.js`、`selectors.js` 继续读扁平数组，几乎不改。

```js
state = {
  currentDate, selectedDate,
  // 真实存储：按文件分组
  availabilityFiles: [
    { id, fileName, uploadedAt, items: [{ itemId, teacher, date, startTime, endTime }] }
  ],
  courseSystemFiles: [
    { id, fileName, uploadedAt, items: [{ itemId, classType, courseName, teacher, duration, scheduled }] }
  ],
  // 派生缓存（= flatMap files → items），供 scheduler/calendar/selectors 使用
  availabilityData: [...],
  courseSystemData: [...],
  courses: [{ id, name, date, startTime, endTime, teacher, type, sourceItemId }],
  // UI 折叠状态
  ui: {
    sectionCollapsed: { availability: false, courseSystem: false, scheduled: false },
    fileCollapsed: { [fileId]: true }   // 默认折叠
  },
  uploadStatus, scheduleStatus
}
```

**itemId 联动**：每个条目带唯一 `itemId`；`courses` 增加 `sourceItemId` 指向来源 courseSystem 条目。删除联动改用 `itemId` 定位（替代现有的 `index` / `id-100`），顺便修复现有 `id-100` 在删除条目后索引错位的潜在 bug。

### 布局

```
┌──────────────────────────────────────┬─────────────────────────┐
│ 顶部条: 📅 月度排课系统  [📅智能排课] │  (横跨左右, 窄条)       │
├──────────────────────────────────────┼─────────────────────────┤
│                                      │  右侧汇总面板 (flex:1)  │
│        左侧日历 (flex:5)             │  ┌───────────────────┐  │
│                                      │  │ 上传区(纵向堆叠)  │  │
│                                      │  │ 空闲表 [选择文件] │  │
│                                      │  │ 课程表 [选择文件] │  │
│                                      │  ├───────────────────┤  │
```

- 顶部条横跨全宽（标题 + 智能排课按钮）。
- 左右主区 `flex: 5 1 0` / `flex: 1 1 0`。
- 右侧面板内部纵向滚动；上传区置顶，三个折叠区依次排列。

### 折叠交互（类似文件夹）

- **区块标题**点击 → 展开/收起整个区块内容（`sectionCollapsed`）。
- **文件节点**点击 → 展开/收起该文件的条目列表（`fileCollapsed[fileId]`）。展开图标 `▶`/`▼` 切换。
- 文件节点右侧有「删除文件」按钮；条目右侧有「删除」按钮。
- 排课结果区块无文件分组，直接展开为条目列表。

## 实现步骤（按文件）

### 1. `app/index.html` — 结构重组
- 顶部条 `<header>`：标题 + 智能排课按钮。
- 主区 `<main class="main-split">`：左 `<section class="calendar-zone">`（日历容器），右 `<aside class="summary-zone">`。
- 右侧：上传区（两张上传卡纵向堆叠）+ 三个 `<section class="tree-section" data-section="availability|courseSystem|scheduled">`（含可点击标题 + 内容容器）。
- 容器 id 调整：`availabilityTreeContent`、`courseSystemTreeContent`、`scheduledTreeContent`。

### 2. `app/src/styles/layout.css` — 左右 5:1
- 删除原上下分区（`.input-zone` / `.output-zone` 的 flex-direction: column 语义）。
- 新增 `.main-split { display:flex; gap:16px; flex:1; min-height:0; }`，`.calendar-zone { flex:5; min-width:0; }`，`.summary-zone { flex:1; min-width:0; display:flex; flex-direction:column; gap:12px; overflow-y:auto; }`。
- 顶部条 `.top-bar { display:flex; align-items:center; justify-content:space-between; padding:12px 20px; }`。

### 3. `app/src/styles/components.css` — 新增树形折叠样式
- 新增类：`.tree-section`、`.tree-section__header`（可点击，cursor:pointer）、`.tree-section__title`、`.tree-section__count`、`.tree-section__body`。
- `.file-node`、`.file-node__header`（点击展开）、`.file-node__toggle`（▶/▼）、`.file-node__name`、`.file-node__body`（展开内容，缩进）、`.file-node__delete`。
- 复用现有 `.delete-btn`、`.data-list-item`、`.data-list-empty`。
- 折叠态用 `[hidden]` 或 `.collapsed { display:none; }`。

### 4. `app/src/styles/course-system.css` — 表格横向滚动
- `.course-system-table-wrap { overflow-x:auto; }` 包裹表格；表格 `min-width` 保证列不挤压。
- 表格在窄列下列宽压缩（padding 减小，已在 12px/11px 字号）。

### 5. `app/src/styles/responsive.css` — 响应式
- 窄屏（≤1100px）：`.main-split` 改 `flex-direction:column`，左右堆叠；右侧面板高度自适应。

### 6. `app/src/state/store.js` — 数据模型 + actions（改动重点）
- `initialState`：新增 `availabilityFiles:[]`、`courseSystemFiles:[]`、`ui:{sectionCollapsed:{},fileCollapsed:{}}`；保留 `availabilityData:[]`、`courseSystemData:[]`、`courses:[]`。
- 新增内部辅助：`_nextFileId()`、`_nextItemId()`、`_rederiveAvailability(state)`、`_rederiveCourseSystem(state)`（flatMap files→items，更新扁平缓存）。
- 新 actions：
  - `addAvailabilityFile(fileName, items)`：生成 fileId/itemId，push 到 `availabilityFiles`，重派生 `availabilityData`，`fileCollapsed[fileId]=true`。
  - `addCourseSystemFile(fileName, items)`：push 到 `courseSystemFiles`，重派生 `courseSystemData`。（不清空 courses，提示需重新排课）
  - `deleteAvailabilityFile(fileId)` / `deleteCourseSystemFile(fileId)`：移除文件；课程体系文件还需同步删除其条目对应的 `courses`（按 `sourceItemId`）；重派生。
  - `deleteAvailabilityItem(itemId)` / `deleteCourseSystemItem(itemId)`：定位所在文件移除条目；课程体系条目若 `scheduled===true` 同步删除对应 course；重派生。
  - `deleteScheduledCourse(index)`：改用 `course.sourceItemId` 找 courseSystem 条目置 `scheduled=null`；移除 course。
  - `toggleSection(key)` / `toggleFile(fileId)`：更新 `ui` 折叠状态。
- `runSchedule()`：调用 `generateSchedule(state)` 后，把返回的 `newCourseSystemData`（扁平，含 itemId+scheduled）**回写到对应文件的 items**（按 itemId 匹配更新 `scheduled`），再重派生。`courses` 携带 `sourceItemId`。
- 保留旧 action 名（`setAvailability`/`setCourseSystem`）可删除或保留为兼容。

### 7. `app/src/scheduler/index.js` — 小改：sourceItemId
- `commitSlot`：`courseItem` 已带 `itemId`（来自 `newCourseSystemData`，因 `courseSystemData` 扁平缓存每项含 itemId）。在 `ctx.scheduledCourses.push({...})` 中增加 `sourceItemId: courseItem.itemId`。`id` 可保留 `originalIndex+100` 或改为自增（不影响）。
- 其余逻辑（`originalIndex`、`newCourseSystemData[originalIndex].scheduled=true`）不变，因 `newCourseSystemData` 仍是扁平数组。

### 8. `app/src/render/dataLists.js` — 重写为树形折叠
- `renderAvailabilityList(state)`：渲染区块标题（含 count）+ 文件节点列表；每个文件节点展开后渲染条目卡片（师资/日期/时间 + 删除按钮，`data-action="delete-availability-item" data-item-id="..."`）；文件节点带删除按钮（`data-action="delete-availability-file" data-file-id="..."`）。
- `renderScheduledList(state)`：渲染排课结果区块标题 + 条目列表（`data-action="delete-scheduled" data-index="..."`，保留 index 或改 itemId）。
- 根据 `state.ui.sectionCollapsed` / `fileCollapsed` 控制 `.collapsed` 类。
- `renderStatus(state)`：基本不变，更新上传/排课状态文本。

### 9. `app/src/render/courseSystem.js` — 重写为树形折叠 + 紧凑表格
- `renderCourseSystem(state)`：区块标题（含统计 `getCourseSystemStats`）+ 文件节点列表；文件节点展开后渲染**紧凑表格**（班型/课程/师资/时长/状态/操作，`overflow-x:auto` 包裹），每行删除按钮 `data-action="delete-course-item" data-item-id="..."`；文件节点删除按钮 `data-action="delete-course-file" data-file-id="..."`。
- 复用 `getCourseSystemStats`（仍读扁平 `courseSystemData`，无需改）。
- 状态列逻辑保留（scheduled true/false/null）。

### 10. `app/src/render/index.js` — 调整渲染调用
- `renderAll` 调用顺序保持：availability、scheduled、courseSystem、calendar、status。

### 11. `app/src/events/bindEvents.js` — 上传累积 + 删除/折叠事件
- 上传空闲时间：`parseAvailabilitySheet(file)` → `addAvailabilityFile(file.name, list)`；状态文本「成功导入 N 条（来自 file）」。
- 上传课程体系：`parseCourseSystemSheet(file)` → `addCourseSystemFile(file.name, list)`。
- 事件委托扩展 `data-action`：
  - `delete-availability-item`（itemId）、`delete-availability-file`（fileId）
  - `delete-course-item`（itemId）、`delete-course-file`（fileId）
  - `delete-scheduled`（index 或改 itemId）
  - `toggle-section`（key）、`toggle-file`（fileId）—— 点击标题/文件头时触发。
- 月份导航、排课按钮不变。

### 12. `app/src/main.js` — 初始 state 适配
- 确认 `initialState` 含新字段；`subscribe(renderAll)` 不变。

## 不需改动的文件
`calendar.js`、`selectors.js`（`getCourseSystemStats`/`getCoursesForDate`/`getAvailabilityForDate`/`getMonthAvailability` 仍读扁平缓存）、`excelParser.js`、`dateUtils.js`、`scheduler/dispersion.js`、`scheduleContext.js`、`trySchedule.js`、`timePriority.js`、`scheduler/constants.js`、`config/constants.js`。

## 验证方法
1. **启动**：`npx vite --port 5173`（在 `app/` 目录），浏览器访问 http://localhost:5173 。
2. **布局**：确认左右 5:1，左侧日历占主导，右侧汇总面板窄列；窄屏（缩窗至 ≤1100px）改为上下堆叠。
3. **多文件累积**：连续上传 2 个空闲时间 Excel → 右侧出现 2 个文件节点，分别展开可见各自条目，日历对应日期显示空闲卡片。
4. **折叠交互**：点击区块标题收起/展开；点击文件节点 ▶/▼ 展开/收起条目。
5. **课程体系表格**：展开课程体系文件节点 → 紧凑表格显示，窄列下可横向滚动。
6. **删除联动**：
   - 删除单个空闲条目 → 日历同步消失。
   - 删除空闲文件 → 该文件所有条目从日历消失。
   - 排课后删除课程体系条目 → 对应排课结果同步删除；删除排课结果 → 课程体系该条目状态重置为 null。
   - 删除课程体系文件 → 其所有排课结果同步删除。
7. **排课**：点「智能排课」→ 日历显示排课结果，课程体系表状态列更新（✓已排课 / ✗无空闲时间），排课结果区块显示条目。
8. **控制台**：无报错；排课日志（`师资 X: 成功排课 N/M`）正常输出。
