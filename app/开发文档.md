## 1. 项目概述

### 1.1 项目简介

月度排课系统是一个基于纯前端的课程安排工具，核心功能是根据师资空闲时间表和课程体系表，自动生成满足约束条件的月度课程日历。支持多文件累积上传、树形折叠浏览、智能排课与删除联动。

### 1.2 技术栈

- **构建工具**: Vite 5（原生 JS ESM，无框架）
- **Excel 解析**: SheetJS（xlsx，npm 依赖）
- **样式**: CSS 变量 + Flexbox/Grid，按模块拆分
- **状态管理**: 自实现 pub/sub（发布-订阅）
- **无后端**: 纯前端实现，数据仅在浏览器内存中存储

### 2.2 排课约束条件

#### 硬约束（必须满足）

1. **空闲时间**: 课程时间必须完全落在师资的空闲时间段内，且时长等于课程时长
2. **师资课程间隔**: 同一师资的课程之间必须保持最小间隔（≥5分钟）
3. **班级课程间隔**: 同一班级的课程之间必须保持最小间隔（≥5分钟）
4. **时间顺序递增**: 课程按子表内的排列顺序依次排课，后一个课程的开始时间必须晚于前一个课程（按子表内师资独立追踪）

#### 软约束（建议满足）

1. **课程间隔**: 两门课程之间建议保持 10 分钟间隔（无法满足时回退到 5 分钟）
2. **课程分散**: 按空闲天数与课程数量的比值间隔排课（详见分散策略）
3. **时间优先级**: 优先选择晚上时间段（18:00-22:30），其中 19:00 为最优时间点
4. **师资排课优先级**: 按师资排课难易程度降序排课，难易程度高的师资优先排课（详见师资难易程度评估）

#### 约束回退机制

```text
六级回退（按优先级从高到低）:
Level 1: 仅晚上 + 10分钟间隔（最优方案）
  ↓
Level 2: 仅晚上 + 5分钟间隔（放宽间隔）
  ↓
Level 3: 仅晚上 + 无间隔（间隔最宽松）
  ↓
Level 4: 所有空闲 + 10分钟间隔（放宽时间范围）
  ↓
Level 5: 所有空闲 + 5分钟间隔（双重放宽）
  ↓
Level 6: 所有空闲 + 无间隔（最后回退）
  ↓ 仍无法排课
标记为「✗ 无空闲时间」

注意: 
- trySchedule.js 中的分散度奖励机制在所有 Level 中均生效
- 分散度奖励基于已排课程的日期分布，鼓励课程跨周分散
- 即使在「仅晚上」模式下，如果晚上时间分散在不同周，分散度奖励也会鼓励选择跨周的晚上时间
- 班级间隔始终为 5 分钟，无回退
```

### 2.3 课程分散策略

#### 策略算法
```text
1. 按师资分组课程
2. 评估每个师资的排课难易程度，按难易程度降序排课（难排的优先）
3. 统计每个师资的空闲天数（去重、排序）
4. 冲突感知过滤：剔除已被其他师资/班级占满（无可放下课程时间槽）的日期（v5.13）
5. 生成多策略分散方案（线性/间隔/贪心/分段）+ 局部搜索精炼，选全局最优（v5.13）
6. 第一阶段：按选中日期逐个排课（考虑分散度）
7. 第二阶段：补排未成功的课程（跳过分散度，确保所有课程都排入）
```

> 多 Sheet 共享同一班级日历时，Sheet 按其"最难师资"难易程度降序排课，难 Sheet 先排（v5.13）。

#### 分散维度（v5.12 核心改进）
```text
分散度只在"师资+班级"维度内生效：

✓ 同一师资 + 同一班级：需要分散
  例：窦峥老师的"27OMO"课程需要跨周分散

✗ 不同师资或不同班级：不需要分散
  例：窦峥的"27OMO"与方浩的"27OMO"不需要分散
  例：窦峥的"27OMO"与窦峥的"28OMO"不需要分散
```

#### 补排机制（v5.12 核心改进）
```text
硬约束优先级 > 课程排完第一优先级 > 分散度优化

第一阶段（正常排课）：
  - 考虑分散度奖励
  - 同一天可排多个课程（移除原有的2节课限制）
  - 只检查硬约束：师资时间不重叠、班级时间不重叠

第二阶段（补排）：
  - 对未排成功的课程，跳过分散度计算
  - 使用所有可用日期（不限制晚上时间）
  - 确保所有课程都排入是第一优先级
```

### 2.4 师资难易程度评估（v5.11）

#### 评估公式

```
难易程度 = 课程时间总需求 / 空闲时间总量

其中：
- 课程时间总需求 = Σ(课程时长)，单位分钟
- 空闲时间总量 = Σ(每个空闲时间段的 endTime - startTime)，单位分钟
```

#### 排序规则

- 难易程度值越大 → 排课越困难 → 优先排课
- 难易程度值越小 → 排课越容易 → 后排课
- 无空闲时间的师资（∞）最优先排课

#### 示例

| 师资 | 课程需求  | 空闲时间   | 难易程度  | 排课顺序  |
| -- | ----- | ------ | ----- | ----- |
| 窦峥 | 270分钟 | 360分钟  | 75.0% | 1（优先） |
| 王芳 | 180分钟 | 720分钟  | 25.0% | 2     |
| 方浩 | 120分钟 | 1200分钟 | 10.0% | 3（最后） |

#### 设计原理

- **稀缺资源优先**：空闲时间相对课程需求越紧张的师资，排课越困难
- **避免资源挤占**：难排的师资先排课，避免被易排的师资占用共享日期
- **提高成功率**：先解决困难师资，确保整体排课成功率最大化

#### 诊断信息输出

排课过程中会输出每个师资的难易程度评估：

```
[基础班] 师资排课难易程度评估:
  窦峥: 课程需求 270分钟 / 空闲 360分钟 = 75.0%
  王芳: 课程需求 180分钟 / 空闲 720分钟 = 25.0%
  方浩: 课程需求 120分钟 / 空闲 1200分钟 = 10.0%
```

#### 时间槽选择策略（v5.10 核心改进）

```javascript
// 收集所有候选时间槽，综合评分选择最优
// 评分 = 时间优先级评分 + 分散度奖励

function calculateTimeSlotScore(timeScore, targetDate, existingScheduledDates) {
  // 时间优先级评分：19:00为最优（200分），晚上>下午>上午
  
  // 分散度奖励：基于与已有课程日期的间隔
  const dateDay = parseInt(targetDate.slice(-2));
  let minGap = calculateMinGapFromExisting(dateDay, existingScheduledDates);
  
  // 间隔越大，奖励越高
  if (minGap >= 10) return timeScore + 100;  // 强奖励，鼓励跨周分散
  if (minGap >= 7) return timeScore + 80;
  if (minGap >= 5) return timeScore + 60;
  if (minGap >= 3) return timeScore + 40;
  if (minGap >= 1) return timeScore + 20;
  return timeScore + 0;
}
```

| 间隔天数 | 分散度奖励 | 说明         |
| ---- | ----- | ---------- |
| ≥10天 | +100  | 强奖励，鼓励跨周分散 |
| ≥7天  | +80   | 推荐         |
| ≥5天  | +60   | 良好         |
| ≥3天  | +40   | 可接受        |
| ≥1天  | +20   | 最小分散       |
| 0天   | +0    | 同一天（不推荐）   |

**设计思路**：

- 晚上时间评分190分 + 跨周奖励100分 = 290分（最佳选择）
- 下午时间评分130分 + 跨周奖励100分 = 230分（良好选择）
- 晚上时间评分190分 + 同周奖励0分 = 190分（次选）
- 这样鼓励课程优先分散到不同周，同时保持晚上时间的优先级

#### 分散度评价函数

```javascript
// allDates 为整月所有日期（1日~月末），按整月时间轴评分，而非空闲日期子集
function calculateDispersionScore(dates, allDates) {
  // 1. 覆盖范围评分：课程覆盖整个月的程度（权重最高）
  const coverage = (lastIdx - firstIdx) / totalRange;
  const coverageScore = coverage * 100;

  // 2. 均匀度评分：间隔标准差越小越好
  const uniformityScore = 1 / (1 + stdDev);

  // 3. 最小间隔评分：最小间隔越大越好
  const minGapScore = minGap;

  // 4. 平衡性评分：最大间隔与最小间隔差距越小越好
  const balanceScore = 1 / (1 + gapRange);

  // 5. 大间隔惩罚：超过7天的间隔额外扣分，强制方案不能有一周以上空白期
  for (const g of gaps) {
    if (g > 7) largeGapPenalty -= (g - 7) * 10;
  }

  // 6. 中间覆盖奖励：方案中的日期落在月中间区域(15%~85%)的比例越高，分数越高
  const midRatio = midCount / dateIndices.length;
  const midCoverageBonus = midRatio * 30;

  return coverageScore + uniformityScore * 50 + minGapScore * 5
       + balanceScore * 20 + largeGapPenalty + midCoverageBonus;
}
```

| 指标    | 权重    | 说明                          |
| ----- | ----- | --------------------------- |
| 覆盖范围  | 100   | 课程是否覆盖整个月（按整月所有日期衡量），越全面越好  |
| 均匀度   | 50    | 间隔标准差越小，评分越高                |
| 平衡性   | 20    | 最大间隔与最小间隔差距越小，评分越高          |
| 中间覆盖  | 30    | 日期落在月中间区域(15%\~85%)的比例，越高越好 |
| 最小间隔  | 5     | 最小间隔越大，评分越高                 |
| 大间隔惩罚 | -10/天 | 超过7天的间隔，每超出1天扣10分           |

#### 分散策略：贪心优化（v5.1 核心改进）

```
采用贪心优化直接搜索最佳日期组合，而非生成多个方案再评分：

1. 先选取第一个和最后一个可用日期作为锚点
2. 迭代遍历剩余候选日期
3. 对每个候选日期，计算「当前已选 + 该候选」的分散度评分
4. 选择使评分增量最大的候选日期
5. 重复直到选满 totalCourses 个日期

优势：
- 直接优化目标函数（分散度评分），而非间接生成方案
- 确保选中的日期组合是局部最优的
- 天然覆盖中间日期（如11号、21号），只要它们能提升评分
```

> **v5.13 增强**：单一贪心易陷局部最优，现综合多策略方案（线性/间隔/分段/贪心）并加 `localSearchRefine`（1-for-1 爬山）精炼，由 `pickBestPlan` 选全局最优。详见更新日志 v5.13。

#### 时间优先级评分

```
同一天时间段优先级：晚上 > 下午 > 上午
粒度优先级：整点 > 半点 > 整10分 > 整5分（非5分时间不可用）

19:00        → 200 分（最优）
18:00-22:30  → 140-200 分（越接近 19:00 越高）
14:00-17:00  → 90-150 分（越接近 14:00 越高）
09:00-12:00  → 40-90 分（越接近 09:00 越高）
其他时段     → 10-40 分
```

#### 六级排课流程（日期优先级 × 间隔优先级）

```
课程 → Level 1: 仅晚上 + 10分钟间隔 → 成功? → 排课完成
       ↓ 否
     Level 2: 仅晚上 + 5分钟间隔 → 成功? → 排课完成
       ↓ 否
     Level 3: 仅晚上 + 无间隔 → 成功? → 排课完成
       ↓ 否
     Level 4: 所有空闲 + 10分钟间隔 → 成功? → 排课完成
       ↓ 否
     Level 5: 所有空闲 + 5分钟间隔 → 成功? → 排课完成
       ↓ 否
     Level 6: 所有空闲 + 无间隔 → 成功? → 排课完成
       ↓ 否
     标记「无空闲时间」

说明：
- trySchedule.js 中的分散度奖励机制在所有 Level 中均生效
- 即使在「仅晚上」模式下，分散度奖励也会鼓励选择跨周的晚上时间
```

| Level | 日期范围 | 间隔   | 说明     |
| ----- | ---- | ---- | ------ |
| 1     | 仅晚上  | 10分钟 | 最优方案   |

## 3. 数据结构

### 3.1 状态树（store.js）

数据模型采用\*\*「文件分组真实存储 + 扁平数组派生缓存」\*\*双层结构：

- 真实存储为按文件分组（支持多文件累积、树形折叠展示）
- 扁平数组是派生缓存（供排课算法/日历/selectors 使用，无需改动算法）

```javascript
state = {
  currentDate: new Date(),       // 当前显示月份
  selectedDate: new Date(),      // 选中日期

  // ===== 真实存储：按文件分组 =====
  availabilityFiles: [           // 师资空闲时间文件列表
    {
      id: "file-1",              // 文件唯一 ID
      fileName: "空闲时间1.xlsx",
      uploadedAt: 1785895486682,
      items: [
        { itemId: "item-1", teacher: "窦峥", date: "2026-08-05",
          startTime: "19:00", endTime: "21:00" }
      ]
    }
  ],
  courseSystemFiles: [           // 课程体系文件列表
    {
      id: "file-2",
      fileName: "课程体系.xlsx",
      uploadedAt: ...,
      items: [
        { itemId: "item-5", classType: "一年级数学班", courseName: "整数运算",
          teacher: "窦峥", duration: "90", scheduled: null }
      ]
    }
  ],

  // ===== 派生缓存（= flatMap files → items）=====
  availabilityData: [...],       // 供 scheduler/calendar/selectors 使用
  courseSystemData: [...],

  // ===== 排课结果 =====
  courses: [
    { id: 101, name: "整数运算", classType: "基础班", date: "2026-08-05",
      startTime: "19:00", endTime: "20:30",
      teacher: "窦峥老师", type: "scheduled",
      sourceItemId: "item-5" }   // ★指向来源 courseSystem 条目，用于删除联动
  ],

  // ===== UI 折叠状态 =====
  ui: {
    sectionCollapsed: { availability: false, courseSystem: false, scheduled: false },
    fileCollapsed: { "file-1": true }   // true=折叠
  },

  uploadStatus: {
    availability: { text: "等待上传", kind: "info" },
    courseSystem: { text: "等待上传", kind: "info" }
  },
  scheduleStatus: { text: "", kind: "" }
}
```

### 3.2 itemId 联动机制（核心）

每条记录带唯一 `itemId`；`courses.sourceItemId` 指向来源 courseSystem 条目。删除联动通过 `itemId` 定位，**不再依赖数组 index**（避免删除后索引错位）。

| 操作            | 联动行为                                                        |
| ------------- | ----------------------------------------------------------- |
| 删除排课结果        | 找 `sourceItemId` 对应的 courseSystem 条目 → `scheduled` 置 `null` |
| 删除课程体系条目（已排课） | 同步删除 `sourceItemId` 匹配的排课结果                                 |
| 删除课程体系文件      | 同步删除该文件所有条目对应的排课结果                                          |
| 删除空闲时间条目/文件   | 仅影响日历空闲卡片显示                                                 |

### 3.3 scheduled 状态

| 值       | 含义              |
| ------- | --------------- |
| `null`  | 未排课（初始/删除排课后重置） |
| `true`  | 已排课             |
| `false` | 排课失败（无空闲时间）     |

## 4. 排课算法

### 4.1 算法概览（多班级·多师资支持）

```text
generateSchedule(state)  纯函数，输入 state 输出排课结果

1. 验证输入（availabilityData / courseSystemData 非空）
2. 筛选当月空闲时间 monthAvailability
3. 深拷贝课程体系表，重置 scheduled = false
4. 【v5.14】按 classType 分组课程，班级内按 orderInSheet 排序
5. 【v5.14】班级按"最难师资"难易程度降序排序
6. 逐班级排课：
   ├─ 班级内按师资难易程度降序排序
   └─ 逐师资排课：
      ├─ 4-1. 构建师资-班级空闲时间表（师资空闲 - 班级课程时间表，含 CLASS_MIN_GAP 缓冲）
      ├─ 4-2. 预计算分散度方案（冲突感知过滤 + 多策略方案 + 局部搜索精炼）
      ├─ 4-3. 第一阶段：正常排课（使用 teacherCtx，六级回退，计划日期锚定）
      ├─ 4-4. 第二阶段：补排（使用原始 ctx，跳过分散度，确保所有课程排入）
      └─ 4-5. 师资-班级空闲时间表自动销毁，班级课程时间表已自动更新
7. 生成诊断信息 diagnostics（师资统计、班级分布、难易程度）
8. 返回 { courses, courseSystemData, successCount, failedCount, diagnostics }
```

> **v5.14 核心改进**：排课循环从 Sheet→课程 改为 班级→师资→课程，每个师资排课前显式构建师资-班级空闲时间表（师资空闲时间减去班级课程时间表），在数据层面消除班级冲突。

### 4.2 多班级·多师资数据结构

```javascript
// 排课上下文（scheduleContext.js）
{
  teacherScheduleByDate: {
    [teacher]: {
      [date]: [{ startTime, endTime }, ...]   // 师资某日的所有时间段
    }
  },
  classScheduleByDate: {
    [classType]: {
      [date]: [{ startTime, endTime }, ...]   // 班级某日的所有时间段
    }
  },
  scheduledCourses: [],   // 全局已排课程
  dayCourseCounts: {}     // [date] = count
}
```

**核心特性**：

- **跨师资冲突检测**：所有师资共享同一个 `ctx`，A 老师的课会阻止 B 老师在同时段排课
- **跨班级冲突检测**：同一 `classType` 的不同课程（即使不同老师）也会检测时间冲突
- **优先级排课**：课程多的师资优先排课，确保高需求师资获得最优时间

### 4.3 核心函数（scheduler/）

| 函数                                                    | 文件                 | 说明                                                    |
| ----------------------------------------------------- | ------------------ | ----------------------------------------------------- |
| `generateSchedule(state)`                             | index.js           | 排课主入口，协调各模块                                           |
| `commitSlot(ctx, data, course, teacher, slot)`        | index.js           | 落账：注册时间槽 + 写入课程 + 标记 scheduled=true + 记录 sourceItemId |
| `createScheduleContext(monthAvailability)`            | scheduleContext.js | 创建排课上下文（教师/班级课表、冲突检测）                                 |
| `hasConflict(ctx, ...)`                               | scheduleContext.js | 师资/班级冲突检测                                             |
| `findBestDispersionPlan(dates, n, teacher, avail)`    | dispersion.js      | 生成方案+评分，返回 primary/secondary                          |
| `calculateDispersionScore(...)`                       | dispersion.js      | 分散度评分（覆盖范围权重 100）                                     |
| `tryScheduleCourse(ctx, course, teacher, dates, gap)` | trySchedule.js     | 在目标日期查找可用时间槽                                          |
| `calculateTimePriorityScore(minutes)`                 | timePriority.js    | 时间优先级评分（19:00 最优）                                     |

### 4.4 冲突检测

```
新课程时间段: [slotStart, slotEnd]
已有课程: [eStart, eEnd]
最小间隔: gapMinutes（师资：建议10/最低5；班级：固定5）

无冲突条件（满足任一）:
  slotEnd + gapMinutes <= eStart    // 新课程在已有课程之前
  slotStart - gapMinutes >= eEnd    // 新课程在已有课程之后
```

### 4.5 排课后状态回写（store.js runSchedule）

排课算法返回的 `newCourseSystemData` 是扁平数组（含 itemId + scheduled）。`runSchedule` 按 `itemId` 将 `scheduled` 状态**回写到对应文件的 items**，再重新派生扁平缓存：

```javascript
const scheduledMap = new Map(result.courseSystemData.map(it => [it.itemId, it.scheduled]));
courseSystemFiles = state.courseSystemFiles.map(f => ({
  ...f,
  items: f.items.map(it => ({ ...it,
    scheduled: scheduledMap.has(it.itemId) ? scheduledMap.get(it.itemId) : it.scheduled
  }))
}));
```

### v5.11 — 师资难易程度评估

**问题描述**：原师资排课顺序仅按课程数量降序排列，未考虑空闲时间充裕程度。课程数量相同的师资，空闲时间少的应该优先排课，避免被空闲时间多的师资占用共享日期。

**解决方案**：引入师资排课难易程度评估，按难易程度降序排课。

#### 难易程度计算公式

```
难易程度 = 课程时间总需求 / 空闲时间总量

课程时间总需求 = Σ(课程时长)，单位分钟
空闲时间总量 = Σ(每个空闲时间段的 endTime - startTime)，单位分钟
```

#### 排序规则

- 难易程度值越大 → 排课越困难 → 优先排课
- 难易程度值越小 → 排课越容易 → 后排课
- 无空闲时间的师资（∞）最优先排课

#### 实现方式

```javascript
// 评估每个师资的难易程度
const teacherDifficultyList = teachersInSheet.map(teacher => {
  const teacherCoursesInSheet = courses.filter(c => c.teacher === teacher);
  const courseDemandMinutes = teacherCoursesInSheet.reduce(
    (sum, c) => sum + durationToMinutes(c.duration), 0
  );
  const teacherAvailabilities = monthAvailability.filter(a => a.teacher === teacher);
  const availabilityMinutes = teacherAvailabilities.reduce(
    (sum, a) => sum + (timeToMinutes(a.endTime) - timeToMinutes(a.startTime)), 0
  );
  const difficulty = availabilityMinutes > 0
    ? courseDemandMinutes / availabilityMinutes
    : Infinity;
  return { teacher, difficulty, courseDemandMinutes, availabilityMinutes };
});

// 按难易程度降序排列
teacherDifficultyList.sort((a, b) => b.difficulty - a.difficulty);
```

#### 诊断信息增强

`teacherStat` 新增字段：

- `difficulty`: 难易程度比值（0\~1，或 null 表示无空闲时间）
- `difficultyPercent`: 难易程度百分比（0\~100，或 null）
- `courseDemandMinutes`: 课程时间总需求（分钟）
- `availabilityMinutes`: 空闲时间总量（分钟）

排课日志输出示例：

### v5.12 — 分散维度限定、补排机制与课程顺序排课

**问题描述**：
1. 分散度全局生效，导致不同师资或不同班级之间也会产生不必要的分散
2. 一天内最多只能排2节课的限制过于严格
3. 分散度优化可能导致部分课程无法排入
4. 排课未按课程体系表顺序，而是按师资分组排课

**解决方案**：

#### 1. 分散维度限定
分散度只在"师资+班级"维度内生效：
- ✓ 同一师资 + 同一班级：需要分散
- ✗ 不同师资或不同班级：不需要分散

#### 2. 移除每天2节课限制
- 一天内可排多个课程
- 只检查硬约束：师资时间不重叠、班级时间不重叠

#### 3. 新增补排机制
```
第一阶段（正常排课）：
  - 考虑分散度奖励
  - 使用六级回退策略
  
第二阶段（补排）：
  - 对未排成功的课程，跳过分散度计算
  - 使用所有可用日期
  - 确保所有课程都排入是第一优先级
```

#### 4. 严格按课程体系顺序排课
```
之前：按师资分组 → 按师资难易程度排序 → 逐个师资排课
现在：严格按课程体系表的 orderInSheet 顺序 → 逐个课程排课

排课流程：
1. 按 sheetIndex 分组
2. 每个 sheet 内按 orderInSheet 排序（保持课程体系表顺序）
3. 预计算每个师资的分散度方案
4. 按课程体系顺序逐个排课（使用对应师资的分散度方案）
5. 补排未成功的课程
```

**实现方式**

```javascript
const failedCourses = courses.filter(c => !scheduled);
for (const courseItem of failedCourses) {
  slot = tryScheduleCourse(ctx, courseItem, teacher, allDates, level.gap, true);
}
```

### v5.13 — 分散方案精炼、冲突感知规划与多师资测试增强

**背景**：扩展测试数据至 5 位师资、54 门课（共享同一班级 28OMO 的 9 月课表），对照约束条件与分散度分析后暴露三类问题。

**问题描述**：
1. **贪心分散方案陷入局部最优**：单一贪心策略（先选首尾锚点，再迭代选增量最大的日期）可能在某一步选了次优日期，后续无法跳出，导致最终方案出现相邻天（gap=1），而存在评分更高且无相邻天的方案未被探索。
2. **分散方案未考虑跨师资班级冲突**：分散度方案基于师资自身可用日期生成，但当多个师资共享同一班级日历时，方案中提出的日期可能已被其他师资占满（无可放课程的时间槽），导致该日期实际不可行，课程被迫回退到非计划日期。
3. **Sheet 顺序使易排师资挤占难排师资共享日期**：当多个 Sheet 共享同一班级日历且师资可用时间互补（如 A 师资仅晚上可用、B 师资全天可用）时，按工作簿顺序排课会让易排师资（全天可用）先拿到晚上时段，难排师资（仅晚上可用）的最后一门课找不到可用晚上时段。

**解决方案**：

#### 1. 分散方案选择优化（dispersion.js）
不再依赖单一贪心方案，而是综合多种策略方案并用局部搜索精炼，选全局最优：

```
findBestDispersionPlan(availableDates, totalCourses, ...):
  1. generateDispersionPlans 生成多个候选方案：
     - evening-priority：晚上时间专用（按索引线性分布）
     - priority-linear-spread / priority-linear-even：优先级数组线性/中点分布
     - priority-offset-{N} / priority-interval-{N}：偏移与间隔方案
     - segment-full-range：首尾锚定 + segmentSpread 中间填充（覆盖中间间隙日期）
  2. 额外加入 greedyOptimize（贪心增量最大）方案
  3. pickBestPlan 选评分最高方案后执行 localSearchRefine：
     - 1-for-1 替换爬山：遍历已选日期，尝试用未选候选日期替换
     - 若替换后评分提升（>0.001 阈值），接受替换
     - 重复直到无改进或达 100 次迭代上限
  4. 分两级：primary（仅晚上，晚上时间足够时）→ secondary（所有空闲）
```

局部搜索精炼跳出贪心局部最优，能消除本可避免的相邻天。

#### 2. 冲突感知分散规划（index.js + scheduleContext.js）
在计算分散方案前，过滤掉已被其他师资/班级占满的日期，确保方案可行性：

```javascript
// scheduleContext.js 新增 hasAnyFeasibleSlot
export function hasAnyFeasibleSlot(ctx, { teacher, classType, date, durationMinutes }) {
  // 该师资+班级+日期已排过课 → 不可行（硬约束：每天每师资每班级一节）
  if (hasTeacherClassOnDate(ctx, { teacher, classType, date })) return false;
  // 遍历该日该师资所有空闲段，5 分钟步长搜索是否存在无冲突时间槽
  for (const avail of dateAvailabilities) {
    for (let offset = 0; offset <= availEnd - availStart - durationMinutes; offset += 5) {
      if (!hasConflict(ctx, { teacher, classType, date, slotStart, slotEnd, minGap: 0 })) {
        return true;
      }
    }
  }
  return false;
}

// index.js 在预计算分散方案时过滤
const feasibleDates = allTeacherDates.filter(d =>
  hasAnyFeasibleSlot(ctx, { teacher, classType, date: d, durationMinutes: repDuration })
);
const bestPlan = findBestDispersionPlan(feasibleDates, ...);
```

#### 3. Sheet 按最难师资难易程度降序排课（index.js）
当多个 Sheet 共享同一班级日历时，按各 Sheet 中"最难师资"的难易程度降序排课，难排的 Sheet 先排：

```
1. 为每个 Sheet 计算其"最难师资"的难易程度（课程时间总需求/空闲时间总量）
2. Sheet 按"最难师资难易程度"降序排序；同分则按原 sheetIndex
3. 难 Sheet 先排 → 其受约束师资拿到所需晚上时段
4. 易 Sheet 后排 → 其全天可用师资自动让出晚上时段，使用下午/上午时段
```

这样难排师资（仅晚上可用）优先获得晚上时段，易排师资（全天可用）通过班级冲突检测自动改用下午/上午时段。

#### 4. 测试脚本增强（test-e2e.mjs）

### v5.14 — 班级→师资→课程循环结构重构

**背景**：用户要求优化排课逻辑，对每个班级显式建立班级课程时间表，每个师资排课前构建师资-班级空闲时间表（师资空闲时间减去班级课程时间表），确保硬约束在数据层面而非运行时检查层面得到保障。

**核心变更**：

#### 1. 新增 buildTeacherClassAvailability 函数（scheduleContext.js）

```text
输入：师资空闲时间 + 班级课程时间表（ctx.classScheduleByDate）
处理：对每个空闲时间段，用班级已排课程时段（含 CLASS_MIN_GAP 缓冲）做差集
输出：过滤后的空闲时间列表（仅包含未被班级占用的时段）

示例：
  师资空闲：09:00-12:00
  班级课程：10:00-11:00（其他师资的课）
  缓冲区间：09:55-11:05（左右各加 5 分钟）
  结果碎片：09:00-09:55, 11:05-12:00
```

#### 2. 重构排课循环结构（index.js）

```text
旧结构（v5.13）：
  Sheet → 课程（按 orderInSheet 顺序）
  └─ 冲突检测依赖 hasConflict 运行时检查

新结构（v5.14）：
  班级 → 师资 → 课程
  ├─ 1. 为每个班级建立班级课程时间表（ctx.classScheduleByDate）
  ├─ 2. 班级内按师资难易程度降序排课
  ├─ 3. 每个师资排课前：
  │    ├─ 构建师资-班级空闲时间表（师资空闲 - 班级课程时间表）
  │    ├─ 用过滤后的空闲时间排课（tryScheduleCourse 使用 teacherCtx）
  │    └─ 排课结果自动更新到班级课程时间表（registerSlot）
  ├─ 4. 补排阶段：回退到原始空闲时间，让 hasConflict 兜底
  └─ 5. 师资-班级空闲时间表自动销毁（临时变量，离开作用域即 GC）
```

#### 3. 两阶段排课的上下文策略

| 阶段 | 使用的上下文 | 空闲时间来源 | 冲突检测方式 |
|------|------------|------------|------------|
| 正常排课 | teacherCtx | 师资-班级空闲时间表（预过滤） | hasConflict（兜底，检测师资跨班级冲突） |
| 补排 | ctx（原始） | 师资原始空闲时间 | hasConflict（完整检测，含班级冲突） |

**设计要点**：
- 正常阶段使用预过滤的空闲时间，班级冲突在数据层面已消除
- 补排阶段回退到原始空闲时间，因为补排是最后手段，需要最大可能排入课程
- `teacherCtx` 与 `ctx` 共享 `teacherScheduleByDate`/`classScheduleByDate`（浅拷贝），排课结果自动回写
